# 集約統計を未割当プレイヤーの標本だけにする（2026-09-23）

## 何が違っていたか

`HierarchicalDistributedExploration` と Huang 2022 の `DistributedExploration` は、通信の直前に
未割当プレイヤーの推定値だけを `mu_hat`・`N_mat` に書き込んでいたが、**割当済みになったプレイヤーの
古い欄を 0 に戻していなかった**。`_compute_accept_reject` は全 M 人の欄を合計するので、割当済みの
プレイヤーの過去の標本が判定用の統計に残っていた（Codex の 4 回目のレビュー 7.2 節。再現済み）。

論文の仕様（補足 B の集約規則、補題 4 の証明 (2)(a)）は「集約は未割当プレイヤーの標本だけから毎相作り直す」。
Huang 2022 の DistributedExploration も active なプレイヤーの推定値だけを集約する。理論の
統計事象（未割当集合の候補を数える合併限界）と量子化誤差の補題はこの仕様に対するものなので、
実装をこれに合わせた。

## 直したこと

- HDE / DE の通信直前に、割当済みのプレイヤーの `mu_hat`・`N_mat` の欄を 0 に戻す。
- `hde_comm_log` に `n_players_in_aggregate`（集約に入ったプレイヤー数）と `n_unassigned` を足し、
  両者が一致することをテストで確認する。

## 結果への影響

割当済みのプレイヤーの標本が抜けるので、判定に使う標本数が減り、分類がわずかに遅くなりうる。
Huang 2022（n=1）も割当済みフォロワーの標本を使わなくなるので、n=1 の値も変わる。
