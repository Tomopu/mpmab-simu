# 割当規則を案 II（抜ける順番の固定と通信腕の引継ぎ）にする（2026-09-24）

## 何を変えたか

n >= 2 の割当規則（HDE の AssignAndUpdate）を、Codex の案 II（論文リポジトリ `reviews/codex/07_assignment_rule_redesign.md` の 4 節）に変えた。

- 探索から抜ける順番を、内部ランクで π = (n, n-1, ..., 1, M, M-1, ..., n+1) に固定する。リーダーが先、フォロワーが後。
- 受理された腕を腕番号順に処理し、π で最初の未割当者 u に渡す。
- u がフォロワーで、腕が通信腕なら、非通信腕を持つ割当済みリーダーのうちランクが最小の人が通信腕を取り、旧い腕を u に渡す（引継ぎ）。
- 通信の役割（受信担当）は初期のリーダーのまま変えない。フォロワーは通信腕を持たない。
- n = 1 は Huang 型の分岐のまま（割当規則によらず同じ軌跡）。

旧規則（受理された通信腕を担当リーダーへ、通信腕が棄却されたリーダーは救済してフォロワーの列へ）は
`assignment_rule="channel_owner"`（実験名 `izumi2026_channel_owner`）で残す。

## なぜ変えたか

旧規則では、リーダーが自分の通信腕の受理で抜けるので、未割当集合の候補が相ごとに (M - n + 1) 2^n 通りになり、
論文の定理 1 に n >= 2 の仮定 (M - n + 1) 2^n log2 T <= T が要った。案 II では未割当集合が π の末尾に限られ、
候補は相ごとに M 通り（n = 1 と同じ）になる。受理された腕はすぐ割り当てられるので、n >= 2 では待ちの損失も 0 になる。

- 実験：`outputs/camera_ready_20260924_handoff/`（5 設定、2026-09-24、当時の実験名 `izumi2026_handoff`）。
  現行規則（`outputs/camera_ready_20260923/`）と同じ seed で対にして比べた。
  - 不変量の違反（π の末尾でない、引継ぎ元がいない、フォロワーが通信腕を持つ）は全試行で 0。
  - 成功率は下がらない（(10,4) の n=5 は 0.68 → 1.00）。
  - リグレットの変化はほとんど ±1% 以内（最大 +1.9%）。最良の n は変わらず、主設定（ランダム）の削減率は 34.3% → 33.8%。
  - 詳細は論文リポジトリ `reviews/verification/05_handoff_experiment.md`。
- 既定を切り替えた後の `izumi2026` は、`izumi2026_handoff` と同じ seed で数値が完全に一致する（主設定、3 試行、n = 1..3）。
